# Program of Thoughts for Financial Reasoning: Leveraging Dynamic In-Context Examples and Generative Retrieval

这篇论文把通用 `PoT` 明确推进到金融场景，并提出了名为 `FINDER` 的两阶段框架。它的重要性在于指出，金融数值推理的瓶颈并不只有计算环节本身，还包括检索相关事实、从文本和表格中抽出正确证据、以及为当前问题动态匹配合适示例。这使得它比一般 PoT 工作更贴近 `FinQA` 与 `ConvFinQA` 的真实难点。

论文摘要的大意是：尽管大模型能力不断进步，数值推理仍然困难。现有 CoT、ToT 和 PoT 等方法提供了中间推理步骤，但即便在 few-shot 提示下，模型在 `FinQA` 和 `ConvFinQA` 这样的金融数值推理数据集上仍落后于最强方法。为此，作者提出 `FINDER` 框架，第一步通过生成式检索从表格和文本中抽取相关事实，第二步在这些事实之上执行上下文感知的 PoT prompting，并动态选择 in-context examples，从而提升金融推理能力。

在数据集方面，这篇论文围绕 `FinQA` 和 `ConvFinQA` 展开，几乎完全贴着当前 FinQA 方向的核心任务。与只关注答案监督的工作不同，作者把“问题所需的证据是否被正确找出”视为性能关键因素，因此在数据处理与推理设计中都强调表格与文本证据的联合组织。这一视角和 FinQA 的任务结构高度一致，因为 FinQA 的错误很多时候并不是出在公式本身，而是出在前置证据选取与变量绑定。

`FINDER` 的算法框架很清楚。第一阶段是生成式检索器，它不是简单 BM25 风格匹配，而是面向金融推理任务抽取最相关的事实片段，并同时兼顾表格与非结构化文本。第二阶段是在检索出的证据之上进行动态示例选择，再用 context-aware PoT prompting 生成程序化推理路径。换句话说，这个框架把“先找准信息，再写对程序”作为一个整体问题处理，而不是默认上下文已经是干净完备的。

实验层面，论文报告 `FINDER` 在 `FinQA` 和 `ConvFinQA` 上取得了很强结果，并强调该提升来自检索质量与动态示例机制，而不只是程序执行本身。这个结论非常关键，因为它提示金融推理模型如果只优化程序生成模块，往往仍会被错误证据拖垮。尤其在长表、多句文本或多轮对话设置中，前置检索的质量常常直接决定上限。

公开页面中没有明显展示一个同名 GitHub 仓库，因此这篇论文更适合作为方法学参考而不是直接照搬代码。真正值得复用的是它对 pipeline 的定义，也就是把金融推理拆成证据抽取、示例选择和程序求解三个强耦合步骤，并允许在每一步引入显式优化。

对 FinQA 的启发主要体现在两个层面。其一，FinQA 的蒸馏和训练数据不应只保存问题、答案和最终 program，最好还保留高质量证据选择轨迹，让模型学习“程序之前发生了什么”。其二，推理时可以考虑引入动态 exemplar 检索或 case-based prompting，而不是固定 few-shot 模板。这样复用 `FINDER` 的思想后，FinQA 系统就不再只是一个公式生成器，而更像一个先定位证据、再生成程序的完整求解器。
