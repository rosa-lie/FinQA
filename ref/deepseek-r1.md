# DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning

`DeepSeek-R1` 虽然不是金融专用论文，但它几乎定义了近一年推理后训练的主流讨论框架，因此在 FinQA 相关研究中很难绕开。它真正重要的地方不在于某个 benchmark 分数，而在于展示了如何用大规模强化学习激励模型形成推理行为，以及为什么纯 RL 路线最终仍需要冷启动数据、多阶段训练和蒸馏来保证质量与可控性。

论文摘要可以概括为：作者提出 `DeepSeek-R1-Zero` 和 `DeepSeek-R1` 两类模型。前者直接在 base model 上进行大规模强化学习，不经过 SFT 预热，也能自然涌现出推理、自我验证和反思等行为；但它存在可读性差、语言混杂和重复等问题。为了解决这些缺陷，作者进一步提出 `DeepSeek-R1`，在 RL 之前加入冷启动数据，并采用多阶段训练流程，从而让模型兼顾强推理能力和更好的输出质量。论文还公开了从 `DeepSeek-R1` 蒸馏得到的一系列小模型。

从数据和训练设置上看，这篇论文不是围绕某个金融 benchmark，而是围绕推理训练配方展开。它把两次 SFT 与两次 RL 组织成完整的后训练 pipeline：前一阶段用来种下初始推理模式，后一阶段继续发现更优推理行为并做人类偏好对齐。与此同时，论文还展示了一个重要结论，即强大教师模型生成的推理数据可以被蒸馏给更小的 dense 模型，并带来比小模型直接做 RL 更好的效果。

算法框架方面，`DeepSeek-R1` 最重要的贡献是把 reasoning post-training 变成一条工程上可描述的流程。`R1-Zero` 用纯 RL 验证推理能力的可涌现性，`R1` 则用冷启动 + 多阶段 SFT/RL 修复其缺陷，最后再通过蒸馏把强模型的推理模式传给更小模型。这个思路对金融任务非常有用，因为金融场景往往更重视输出规范性、数值稳定性和领域一致性，不可能只追求“模型自己长出推理”。

实验层面，论文报告 `DeepSeek-R1` 在数学、代码和推理 benchmark 上达到与 `OpenAI-o1` 相当的水平，同时蒸馏出的小模型也表现出很强竞争力。这为金融领域提供了一个明确暗示：与其在中小模型上盲目尝试纯 RL，不如先用高质量冷启动推理数据建立规范的过程表示，再把 RL 集中用于少数高价值、可验证、容易设计奖励的任务。

对应公开仓库是 `deepseek-ai/DeepSeek-R1`。从 README 可见，仓库更偏向模型发布、评测展示和使用说明，而不是完整披露训练代码。README 明确描述了其核心框架，包括“基座模型上的大规模 RL”“两次 RL + 两次 SFT 的多阶段 pipeline”以及“基于 Qwen 和 Llama 的多尺寸蒸馏模型”。因此，这个仓库最适合被当作训练路线参考和模型资源入口。

对 FinQA 的启发主要是方法论层面的。第一，若要在 FinQA 上做 RL，应优先选择可验证样本，避免把难以自动打分的开放式金融问答混进同一个奖励体系。第二，纯 RL 并不是最稳妥起点，先做冷启动数据、程序化推理监督和格式约束通常更合理。第三，小模型的金融推理提升很可能更依赖高质量教师蒸馏，而不是直接复制大模型的 RL 过程。就这一点而言，`DeepSeek-R1` 为 FinQA 提供的是训练范式，而不是任务答案。
