# Program of Thoughts Prompting: Disentangling Computation from Reasoning for Numerical Reasoning Tasks

`Program of Thoughts` 是数值推理研究中的一个关键转折点。它提出，不应让语言模型在自然语言思维链里同时承担“推理分解”和“精确计算”两件事，而应让模型专注于生成程序化中间表示，再把计算交给外部解释器执行。对于 `FinQA` 这样的金融数值任务，这一思路几乎天然成立，因为任务本身就带有公式、变量绑定和最终数值验证的结构。

论文摘要的核心内容是：虽然 chain-of-thought prompting 在复杂数值问题上已经很有效，但它把推理和计算都塞进自然语言中，导致模型容易在多步计算中出错。为了解耦计算与推理，作者提出 `Program of Thoughts`，让语言模型生成程序而非纯文本推理，并由外部计算器执行程序得到答案。作者在数学和金融数值推理任务上进行 zero-shot 与 few-shot 评测，结果显示 `PoT` 相比传统 CoT 平均带来大约 12% 的性能提升，并在结合 self-consistency 后进一步刷新多项结果。

在数据集方面，这篇论文覆盖了五个数学数据集以及三个金融问答数据集，金融部分正包括 `FinQA`、`ConvFinQA` 和 `TAT-QA`。这意味着论文并不是在一个抽象数学环境里证明 PoT，而是在与 FinQA 十分接近的真实金融数值任务上验证其有效性。也正因为如此，这篇论文对 FinQA 的方法学意义要大于很多只在一般推理 benchmark 上奏效的工作。

算法框架可以理解为三段式 pipeline。首先，模型根据题目和上下文生成带变量赋值、算术操作和控制结构的程序草案。其次，这段程序被交给外部解释器执行，得到精确中间数值和最终答案。最后，在推理时还可以配合 self-consistency，对多条程序路径进行采样和投票。这种做法把语言模型最擅长的结构化表达，与外部工具最擅长的精确计算结合起来，从根本上降低了数值推理中的幻觉和算错风险。

实验部分是这篇论文最有说服力的地方。作者显示 `PoT` 在 few-shot 和 zero-shot 条件下都优于 CoT，在金融数据集上同样成立。这说明金融推理的关键瓶颈并不只是“多想几步”，而是“把计算过程表达成可执行结构”。从 FinQA 的任务定义来看，这个结论非常契合，因为 FinQA 的 gold program 本来就说明程序化表示比纯自然语言解释更贴近任务本体。

对应代码仓库是 `wenhuchen/Program-of-Thoughts`。论文摘要直接给出了该仓库链接，说明代码与数据均有公开。根据论文定位，这个仓库更可能围绕 prompt 模板、程序生成、执行与评测展开，而不是面向大规模后训练。对 FinQA 研究而言，最值得复用的并不是其具体实现细节，而是它对“中间表示应该长什么样”的定义。

这篇论文对 FinQA 的启发可以说是最直接的一类。第一，FinQA 的训练目标应优先考虑程序轨迹、变量引用和执行结果，而不是只蒸馏自然语言长思维链。第二，若使用 SFT 或 RL，奖励也应尽量围绕程序合法性、执行成功率和答案正确率设计。第三，即使继续保留 CoT，也更适合作为证据组织和问题分解层，而不是最终计算载体。换句话说，在 FinQA 里，CoT 更适合负责“解释如何拆”，PoT 更适合负责“真正去算”。
