# Distilling Reasoning Capabilities into Smaller Language Models

这篇论文讨论的是一个对 FinQA 十分现实的问题：如果大模型已经具备较强的逐步推理能力，如何把这种能力可靠地迁移到更小、部署成本更低的模型上。作者并没有简单模仿整条 CoT，而是提出 `Socratic CoT`，用问题分解和子问题求解的方式，把复杂推理拆成更适合小模型学习的结构。

论文摘要的大意是：逐步推理方法例如 CoT 对大模型非常有效，但其成功往往依赖于更大的参数规模。为此，作者提出一种知识蒸馏方法，将大模型的逐步推理能力蒸馏到小模型中。具体而言，论文引入 `Socratic CoT`，先把原问题分解成一系列子问题，再由专门模型逐个求解，最终形成可执行的推理协作过程。这样一来，复杂推理能力不再要求单个小模型一次性完成全部工作，而是通过组合方式获得。

在数据与任务设置上，这篇论文并不面向金融，而是面向一般复杂推理任务，但其方法与 FinQA 的结构非常相容。FinQA 本身就可以自然拆成若干子步骤，例如证据定位、变量抽取、公式组合、程序执行和答案生成。因此，这篇论文的真正价值不在数据集复用，而在于它提供了一种“如何拆分推理能力”的视角。

算法框架上，作者训练了两个小模型协同工作。一个模型负责问题分解，把原始复杂问题转化成更简单的子问题序列；另一个模型负责子问题求解，并利用这些子问题逐步推进最终答案。这种双模型结构与传统 CoT 的最大区别在于，中间推理被显式对象化，而不是全部隐含在一段自由文本里。对于 FinQA 来说，这几乎可以直接映射成“分解器 + 程序生成器”或“证据规划器 + 执行器”的设计。

实验部分显示，这种蒸馏路线能让小模型在复杂推理任务上明显优于直接模仿终答案或简单 CoT 的训练方式。作者用结果说明，推理能力本身也需要被结构化蒸馏，否则小模型很容易只学到表面叙述风格，而学不到真正的问题分解机制。这个结论与 FinQA 非常相关，因为 FinQA 的 gold program 和步骤监督本质上就属于结构化推理信号。

公开页面中没有看到一个广泛引用的官方 GitHub 仓库，因此这篇论文的复用重点更多在方法层而非具体代码。真正值得借鉴的是其“把大推理拆小、把隐式过程变显式模块”的思路，而不是某个固定脚本实现。

对于 FinQA，这篇论文提供了很有价值的复用方向。一个直接思路是把 FinQA 求解器拆成两个或三个轻量模块，例如先生成证据与操作规划，再生成可执行程序，最后由执行器验证答案。另一个思路是把大模型产生的优质 FinQA 过程数据拆成分解轨迹和子问题答案，分别蒸馏给不同子模块。这样做有望在较小参数规模下保留更多真正的推理结构，而不是只保留结果表面形式。
