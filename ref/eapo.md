# EAPO 论文笔记

论文：Guan 等，2026，*Evidence-Augmented Policy Optimization with Reward Co-Evolution for Long-Context Reasoning*。

这篇论文关注的是长上下文推理中的一个核心问题：如果强化学习只用 final answer 的 outcome reward，那么 reward 会非常稀疏，模型即使答对，也可能是靠“幸运猜中”或者错误证据路径得到正确结果，训练过程并不会显式惩罚 evidence retrieval 的失败。作者认为，在长上下文任务里，真正的瓶颈往往不是后续 reasoning 本身，而是能否先从海量噪声上下文里找到正确证据。基于这个判断，论文提出 EAPO，把优化重点从“只奖励最后答案”转为“同时奖励证据质量和最终答案”，并进一步让 reward model 和 policy 共同演化，以避免 reward model 随着 policy 进步而逐渐失真。

论文先提出了 Evidence-Augmented Reasoning（EAR）范式，把输出严格拆成 `<analysis> -> <evidence> -> <reasoning> -> <answer>` 四段。这个设计的重点不是格式本身，而是把 evidence 作为显式中间状态暴露出来，允许训练阶段直接监督“模型到底取了什么证据”。作者随后用 Tree-Structured Evidence Sampling 做了一个经验验证：对同一个 query 和上下文，先采样多条 evidence path，再采样 reasoning path，用 BFS 构造一棵 evidence/reasoning 树，然后分别用语义相似度评估和 LLM-as-a-Judge 评估每条 path。实验结论很明确：一旦 evidence 固定，reasoning path 的语义多样性会迅速坍缩到 96% 以上的一致，因此单独优化 reasoning judge 几乎没有收益；相反，只要把 evidence 提升上去，最终性能就显著改善。论文据此得出核心判断：在 long-context reasoning 中，evidence extraction 是决定性瓶颈。

基于这个动机，EAPO 在算法层面仍然以 GRPO 为底座。它对每个 query 采样一个 group 的输出，使用标准的 group-relative policy optimization 目标，优势函数来自组内 reward 标准化。真正的变化在 reward 构造。作者把总 reward 写成 `R_total = alpha * R_f + beta * R_e + gamma * R_a`。其中 `R_f` 是格式奖励，检查输出是否满足 EAR 所要求的结构，例如是否包含 `<evidence>` 等标签；如果格式不合法，后续 reward 直接不算。`R_e` 是最关键的新项，也就是 Group-Relative Evidence Reward。做法是：对同一个 rollout group 里所有候选的 evidence block 一起送入 reward model，让 reward model 给出 1 到 5 的整数质量分，再在组内做归一化，形成 `[0,1]` 上的 evidence quality reward。这个设计的意义在于，它不再只看“最后答案对不对”，而是比较“同题不同 rollout 的证据谁更好”，从而给 policy 提供一个稠密得多的过程监督信号。`R_a` 则是最终答案正确性奖励，论文里仍然通过一个 judge model 判定答案是否与 ground truth 语义一致，本质上是 outcome reward。

EAPO 的第二个关键设计是 Adaptive Reward-Policy Co-Evolution。作者认为，如果 reward model 固定不动，那么随着 policy 变强，它可能无法继续区分更细微的 evidence 质量差异，结果就是 reward 信号钝化，训练很快平台化。因此他们引入了 reward-policy co-evolution：在 RL 进行过程中，当前 policy 不断生成新的 rollout，当前 reward model 给这些 rollout 的 evidence 打分；然后通过一个 Outcome Consistency Filter 做数据筛选，只保留那些“高 evidence 分数对应正确答案、低 evidence 分数对应错误答案”的轨迹，用这些 outcome-consistent 的高置信样本继续做 reward model 的 rejection fine-tuning。论文里的公式写成 `theta_RM <- arg min E_(q,o,y)~D_high [ L(R_theta(q,o), y) ]`，本质就是让 reward model 在 policy 生成的新分布上持续校准自己的判别边界。这个机制的目标不是单纯提升 reward model 准确率，而是让 reward model 始终与 policy 的能力水平同步，从而维持高保真的过程监督。

实验部分的主结论比较扎实。作者在 SEAL、LongBench-V1 和 LongBench-V2 的 8 个 benchmark 上比较了 base model、只用 outcome reward 的 GRPO、以及 EAPO。结果显示 EAPO 在三个不同 base model 上都稳定优于 GRPO，尤其在 Qwen3-30B-A3B-Instruct 和 Qwen3-30B-A3B-Thinking 上提升明显，说明 dense evidence supervision 带来的增益并不是某个单一模型的偶然现象。更重要的是，ablation 明确显示：去掉 reward model 共进化后，训练初期仍能涨，但较快平台化；保留 co-evolution 后，训练曲线持续上升，最终 ceiling 更高。Reward model 本身的 Best-of-N Selection Accuracy 也会从 69% 提高到 74%，说明 co-evolution 的确在增强 reward model 的判别能力，而不是只在做表面上的数据回流。超参分析中，evidence reward 的权重不是越大越好，`beta=0.3` 最优，继续增大到 0.5 反而掉点，说明过程监督与结果监督之间需要平衡，不能把模型完全推成“只会找证据、不关心最终答案”。论文还补了一组人工验证，EAPO 生成的 evidence 有 97.3% 能严格支持最终答案，而 GRPO baseline 是 92.6%，以及一组 Needle in a Haystack 检索实验，EAPO 达到了 100% retrieval rate。这些分析共同说明：它不是只提升了评测口径里的 answer score，而是真的让 evidence retrieval 更稳、更准。

如果把这篇论文放回当前 FinQA 项目的上下文里看，它最有价值的地方不是“长上下文”四个字本身，而是它给了一个很清晰的 reward 设计方向：当任务里存在一个对最终答案成败至关重要、但 outcome reward 又覆盖不到的中间过程时，应该把这个中间过程显式暴露出来，并给它构造 group-relative、可演化的过程奖励。当前 FinQA program RL 其实已经有这个雏形，因为 `training/finqa_program_grpo.py` 里已有 `Evidence:` 和 `Program:` 结构，也已经在 reward 中加入了 evidence overlap、program executability、program structure 和 executed answer correctness。但这套 reward 还主要是启发式的规则分解，尤其 evidence 奖励仍然只是“Evidence 中数字是否与 prompt 数字重叠”的 proxy，没有真正学习“这段 evidence 是否足以支持后续 program”。从 EAPO 的角度看，当前 FinQA 训练线最应该借鉴的，是把 evidence quality 单独提升为一个一等过程信号，而不是继续把它当成低权重辅助项。

对当前 FinQA program RL，最直接的落地改造可以分三步。第一步，不改 trainer objective，先改输出协议和数据协议，把 v3 的 `Evidence + Program` 继续保留，并明确把 `Evidence` 视为 rewardable intermediate state，而不仅仅是展示字段。也就是说，训练与评估都应继续要求模型先给 evidence，再给 program，后续所有 reward 都围绕这两个显式中间结构展开。第二步，在现有 GRPO/GSPO 基础上增加一个真正的 evidence reward model，而不是只用数字 overlap。这个 reward model 的输入可以是 `(question, context, predicted_evidence, gold_program, gold_answer)` 的裁剪版本，输出一个 evidence utility score，用来判断这段 evidence 是否充分、是否相关、是否支持构造正确 program。初期不需要像论文那样完全做自由文本 judge，可以先构造弱监督标签，例如：如果 evidence 中覆盖了 gold program 所需的大部分关键数值、关键表项或文本片段，且基于这些证据生成的 program 可执行并能得到正确答案，就标高分；反之标低分。然后在同一 prompt 的多个 rollout 内，对 evidence 质量做 group-relative 归一化，形成类似 EAPO 的 `R_e`。第三步，在 policy 训练跑起来后，再做一个简化版 reward co-evolution。也就是每隔若干 RL step，收集一批 rollout，只保留 outcome-consistent 样本，例如“高 evidence score 且 executed answer correct”与“低 evidence score 且 executed answer wrong”的对比对，继续微调 evidence reward model，让它逐步适应 policy 当前分布，而不是永远停留在最初的弱监督数据上。

如果进一步细化到当前代码实现层面，我认为最可行的切入点有三个。第一，在 `training/finqa_program_grpo.py` 和 `training/finqa_program_gspo.py` 中，把现有 `reward_evidence_support(...)` 从简单的 `evidence_overlap_score(...)` 升级为两段式：先保留原有 numeric overlap 作为低成本先验，再新增一个 `reward_evidence_quality(...)`，由独立的 reward model 或打分器输出 evidence utility 分数。这样做的好处是风险低，因为不会一下子把原有 reward 全推翻。第二，在 `prepare_dataset(...)` 或更上游的数据构造里，尽量为每条样本补出 evidence supervision 所需的“关键证据单元”，例如 gold program 涉及到的数字、表格行列、文本证据 span，哪怕一开始只是粗粒度标签，也足够把 evidence reward 从纯字符串启发式推进到弱监督 PRM。第三，在实验协议上，后续所有 GRPO vs GSPO 或新 reward 方案的 ablation，不应只看 `executed_answer_accuracy` 和 `program_accuracy`，还必须新增 evidence 相关指标，例如 evidence key-number coverage、evidence-to-program consistency、evidence sufficiency judge score、以及 evidence reward model 的 Best-of-N selection accuracy。否则即使引入了 EAPO 思路，也无法判断模型到底是在变得更会找证据，还是只是在 exploit 新 reward。

总的来说，这篇论文对 FinQA 当前工作的真正启发不是“换一个新缩写”，而是把我们已经隐约在做的事情彻底讲清楚：对于程序化金融数值推理，最终答案正确并不是唯一需要优化的对象，能够支持 program 构造的 evidence 质量同样应当进入 RL 的主 reward。EAPO 证明了，当中间过程是决定性瓶颈时，仅靠 outcome reward 往往不够；必须把该过程显式暴露出来，做 group-relative 过程奖励，并在训练中持续校准 reward model。对当前项目而言，这个思路最自然的落地方向就是：从“program correctness + 轻量 evidence overlap”升级到“program correctness + learned evidence quality reward + 周期性 reward model 更新”的 program-evidence co-optimization 框架。
