# 行业研究报告助手（金融垂直）落地方案（SFT 打底 + DPO/RLHF 对齐）

> 本文按你给的 TODO 直接展开：
> 1) 数据集来源选取；2) 多源整合；3) 数据清洗；4) SFT；5) RL。
> 设计思路对齐 MedicalGPT 的完整闭环：**数据构造 → SFT → 偏好建模(RM/DPO) → RL(PPO/GRPO) → 评测与回流**。

---

## 0. 任务定义（先定边界再收数据）

**目标用户**：行业研究员、投研助理、策略分析师。  
**核心输出**：可追溯的“行业研究报告草稿”，而不是泛聊天。  
**能力边界**：
- 能做：信息抽取、事件归因、财务指标推导、行业比较、风险提示。
- 不能做：确定性收益承诺、无证据投资建议、超时点数据推断。

**任务拆分（对齐 DISC-FinLLM 的四模块）**：
1. 金融咨询（概念解释/问答）
2. 金融文本分析（情感、抽取、分类、生成）
3. 金融计算（比率、估值、情景分析）
4. 金融检索问答（政策/公告/研报证据化回答）
5. 报告生成（行业框架+证据+风险）

## 1. TODO-1：如何选取数据集来源？

## 1.1 来源分层（公开 / 自建 / 合成）

### A. 公开数据（快速起盘，建立基础金融能力）
- **FinGPT**：
  - sentiment/headline：用于新闻情绪与事件表述风格；
  - finred/ner：用于实体关系抽取；
  - fiqa/fineval：用于金融问答与客观题。
- **DISC-FinLLM（DISC-Fin-SFT）同类公开语料**：
  - 对齐四类金融任务：咨询、任务、计算、检索增强。
- **Soren-Qwen3-4B-Instruct-Finance-v1（经验参考）**：
  - 重点借鉴“指令化样式与金融问答模板”，不盲目照抄分布。

### B. 自建数据（形成壁垒）
- 券商/机构研报的可授权摘要与标签（观点、催化剂、风险）。
- 财报电话会纪要（管理层指引、问答焦点、预期差）。
- 监管/政策文件（证监会、交易所、央行公开文档）。
- 上市公司公告（回购、并购、定增、减持、诉讼）。

### C. 合成数据（补齐稀缺任务）
- 计算链路样本（含中间步骤、单位、公式解释）。
- 证据冲突样本（训练“澄清/拒答/列出待确认项”）。
- 报告写作多风格样本（保守/中性/激进 + 适用条件）。

## 1.2 选取原则（必须打分）
每个候选数据源用 5 维评分（1~5 分）：
- 任务相关性（是否服务研究报告）
- 真实性与可追溯性（有无原始出处）
- 时效性（是否带日期，是否持续更新）
- 合规可用性（版权/许可是否可训练）
- 噪声水平（格式乱、错标、机器翻译痕迹）

**准入门槛**：总分 >= 18/25 才进入训练池。

## 2. TODO-2：如何整合多源数据集？

## 2.1 统一 Schema（建议 jsonl）

```json
{
  "id": "uuid",
  "task_type": "qa|extract|classify|calc|rag|report|safety",
  "domain": "macro|bank|broker|tmt|consumer|healthcare|energy|...",
  "instruction": "用户问题或任务描述",
  "input": "上下文（新闻/公告/财报片段/表格）",
  "output": "标准答案",
  "references": [
    {"title": "source_name", "url": "...", "as_of_date": "2026-03-01"}
  ],
  "quality_score": 0.0,
  "risk_tags": ["timeliness", "compliance"],
  "split": "train|dev|test"
}
```

## 2.2 多源融合流水线
1. **采集层**：HF datasets/API/爬虫（仅公开可用页面）/内部授权库。
2. **标准化层**：字段映射、编码统一、繁简转换、单位标准化。
3. **标注层**：任务标签、行业标签、风险标签。
4. **去重层**：
   - 精确去重：`title + source + date + hash`；
   - 语义去重：MinHash + embedding 相似度阈值。
5. **分桶层**：按任务、行业、难度做分桶，避免数据偏科。
6. **切分层**：train/dev/test 按时间切分，防止信息泄漏。

## 2.3 配比建议（V1）
- 公开：50%
- 自建：35%
- 合成：15%

> 若上线后发现“报告可读性差”，提高 report/rag 样本占比；若“事实错误高”，提高 extract/qa 与证据约束样本占比。

## 3. TODO-3：如何对数据集进行清洗？

## 3.1 硬清洗（规则可程序化）
- 空值/乱码/HTML 垃圾标签清理。
- 文本长度过滤（过短无信息、过长截断并保留来源段落）。
- 日期规范化（`YYYY-MM-DD`）；无日期样本打 `timeliness_risk`。
- 数值规范化（百分比、小数、货币单位统一）。
- 黑名单过滤（广告文、无来源转载、低质伪原创）。

## 3.2 软清洗（模型 + 人工抽检）
- 事实一致性检查：答案是否被 references 支撑。
- 任务一致性检查：`task_type` 与输出风格是否匹配。
- 逻辑完整性检查：结论是否含假设与风险。

## 3.3 金融场景专用“控噪”
- **时效噪声**：样本必须含 `as_of_date`，过期问答加入“时点声明模板”。
- **口径噪声**：同比/环比/TTM/IFRS/GAAP 口径必须显式标注。
- **合规噪声**：去除“保证收益/明确买卖建议”措辞，替换为风险中性表达。
- **计算噪声**：公式可回放（保存中间步骤），便于后续 verifier。

## 3.4 偏好数据（DPO/RM）清洗规范
- 每条 prompt 至少 2 个候选（chosen/rejected）。
- rejected 样本优先选：
  1) 流畅但事实错；
  2) 结论对但无证据；
  3) 合规风险表达。
- 标注维度：事实性、证据性、逻辑性、量化严谨、合规、安全、可用性。

## 4. TODO-4：SFT 训练方案

## 4.1 阶段化 SFT（推荐）

### Stage-A：金融基础能力（2~3 周）
- 数据：qa/extract/classify/calc 为主。
- 目标：先学“说对”，再学“说好”。

### Stage-B：研究报告能力（2 周）
- 数据：rag/report/safety 为主。
- 目标：结构化输出（结论→证据→假设→风险→待确认项）。

### Stage-C：工具调用监督（1~2 周）
- 数据：含检索、表格计算、引用格式化轨迹。
- 目标：高风险问题先查证再回答。

## 4.2 训练实现建议（映射 MedicalGPT）
- 先 LoRA/QLoRA 快速迭代，再评估是否全参。
- 长样本用 packing + loss mask，减少模板句过拟合。
- 采样权重：`calc/report/rag` 略增权（提升实用度）。
- 安全样本混入 5%~10%（拒答/澄清/免责声明）。

## 4.3 SFT 验收门槛（进入 DPO 前）
- 金融 QA 准确率达到预设基线。
- 抽取类 F1 达标。
- 报告草稿人工可编辑率（编辑时间下降）达标。
- 高风险问题“无证据不下结论”达标。

## 5. TODO-5：RL（DPO/RLHF）训练方案

## 5.1 先 DPO，后 PPO/GRPO（成本与稳定性平衡）
1. **DPO（第一优先）**
   - 在“报告写作 + RAG 证据 + 合规安全”任务上做偏好优化。
   - 目标：提升“可直接用”与“可信”而非只提升流畅度。
2. **RM（可选但建议）**
   - 用 6~7 维 rubric 训练 reward model，增强可解释打分。
3. **PPO/GRPO（小流量高价值任务）**
   - 仅在关键场景开启（行业周报、事件快评）。
   - KL 约束 + 早停，避免语言退化与模式坍缩。

## 5.2 奖励设计（避免“会写但不真”）
总奖励 =
- + 事实奖励（引用可验证）
- + 结构奖励（报告结构完整）
- + 计算奖励（数值正确 + 单位正确）
- + 合规奖励（风险披露充分）
- - 幻觉惩罚（无证据结论）
- - 违规惩罚（确定性收益、诱导交易）

## 5.3 在线反馈回流
- 收集用户编辑轨迹：删改位置、补证据次数、驳回原因。
- 每周增量生成偏好对，每月一次 DPO 小版本。
- 对高频失败样本建立“困难集”，作为固定回归测试。

## 6. 评测与证据链（证明每个组件有效）

## 6.1 自动评测
- 抽取：F1
- 分类：Macro-F1
- 计算：Exact Match + 容差
- 报告：引用命中率、时点一致性、结构完整率

## 6.2 人工评测
- 维度：专业性、可信度、可执行性、合规性、编辑成本。
- 方式：A/B 盲测（SFT vs SFT+DPO vs SFT+DPO+RL）。

## 6.3 强制消融
- 无清洗 vs 有清洗
- 无偏好数据 vs 有偏好数据
- 无 RAG 约束 vs 有 RAG 约束
- 无合规奖励 vs 有合规奖励

## 7. 12 周执行排期（可直接开工）
- 第 1-2 周：数据源盘点、许可审查、schema 与流水线搭建。
- 第 3-5 周：完成 V1 SFT 数据集与 Stage-A/B 训练。
- 第 6-7 周：偏好对构建与 DPO v1。
- 第 8-9 周：RM + 小规模 PPO/GRPO 实验。
- 第 10 周：自动+人工评测与消融实验。
- 第 11-12 周：灰度上线、回流数据、DPO v2。

---

## 8. 最小可行版本（MVP）
1. 用 FinGPT + DISC 同类公开数据起盘，补少量自建研报样本。
2. 做一个“行业周报草稿”单场景助手（最容易验证价值）。
3. 第一阶段只做 SFT + DPO，不急于上 PPO。
4. 用“引用命中率 + 编辑时长下降 + 合规通过率”作为上线 KPI。

> 核心原则：不是做“更会聊天的金融模型”，而是做“能被研究团队审计、复用、合规上线的研究生产系统”。
